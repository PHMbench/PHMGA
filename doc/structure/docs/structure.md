# Docs Structure

## 职责
- 记录结构边界、模块存在理由、重构现状与目标态差距。
- 记录哪些冗余已删、哪些仍在兼容期、删除依据是什么。

## 为什么需要这一层
- 这不是 README 的重复。README 主要回答“怎么用”，而结构文档回答“为什么这样分层、哪些层还能删、哪些兼容不能再扩散”。
- 如果没有单独的结构文档层，重构决策只能埋在 commit message 和零散 issue 里，无法审计。

## 正式入口
- `doc/structure/README.md`
- `doc/structure/index.md`
- `doc/structure/*/structure.md`
- `doc/structure/del/*`

## 输入/输出边界
- 输入：当前仓库结构、测试状态、目标蓝图 [`v1.0.md`](../v1.0.md)。
- 输出：模块说明、冗余清单、目标态差距说明。
- 不负责：替代实现、运行时配置、自动迁移脚本。

## 当前实现状态
- 已实现：每个核心模块都有结构文档，`del/` 维护删除执行清单。
- 正在收口：部分仓库 README、注释和 runbook 仍需逐步跟上结构文档的新术语。
- `v1.0` 目标但未全落地：让结构文档和实际代码迁移节奏保持长期同步，而不是只在一次重构时集中补写。

## 冗余与历史包袱
- 过去只有零散说明，没有“为什么存在这一层”的统一口径，导致重复入口长期存在也难以判断是否该删。

## 按 v1.0 的下一步
- 继续把文档测试和删除动作绑定起来。
- 对所有仍在兼容期的 facade 保持明确的退场条件。
