## 需求与接口对齐（PHMGA ↔ 可解释网络）
   - 本文档是 `doc/paper/goal.md` 的工程化落地计划：外环 Agent 负责改 `model_config.yaml`，内环训练器负责训练/评估并产出结构化反馈；二者闭环迭代。
   - 读者指南（先读这几段就能开工）：
     - 1.x：数据/标签/多通道节点与融合口径（最关键的“能否跑通”部分）
     - 3.x：`model_config.yaml` 的 schema 与 fail-fast 约束（最关键的“能否复现”部分）
     - 4.x+5.x：外环/内环 agent 的接口与产物（最关键的“能否闭环”部分）
   1) 明确数据入口：PHMGA 当前 `InputData.results/ref|tst` 的数组形状、采样率 `fs`、标签来源（root meta.labels）。
   2) 明确网络期望输入：参考 `Unified_X_fault_diagnosis/model/TSPN.py`（`x: [B, L, C]`）与训练所需 label。
   3) 明确输出与解释性目标：分类 logits + 可解释信息（每层算子权重、被选中的算子/特征、关键频带/时域片段等）。
   4) 统一“数据/张量约定”（写入代码校验 + README）：
      - PHMGA 信号：`np.ndarray`，约定形状 `(B, L, C)`。
      - TSPN 输入：`torch.Tensor`，约定形状 `(B, L, C)`；内部如需转置必须转回。
      - 标签：`y: (N,) int64`；`num_classes` 必须**在配置中显式给出**；若缺失则在首次构建数据集时从 `labels_ref` 推断并写回 `model_config`（并在本次 run 冻结，避免训练中途漂移）。
   5) 明确“PHMGA DAG 与 TSPN 的关系”（已确认采用 A）：
      - A（采用，最小侵入）：TSPN 作为“训练后端”，不强行并入现有 numpy-DAG builder loop；DAG 继续服务于信号处理/特征/浅层模型等流程。
      - B（进阶，可选，后续再做）：把“模型训练/推理/解释”也纳入 DAGTracker（需要新增 node schema 与序列化策略）。
   6) TSPN 的“多通道 = 多个节点（每个通道一个节点）”约定（你已更新）：
      - 数据在图中按通道拆分：`ch1..chC` 为多个节点；每个节点的 `results.ref/tst` 是 `{sample_id: (1,L,1)}`。
      - TSPN 仍然需要 `(B,L,C)`，但**不把多通道折叠为单节点存储**；而是在训练/推理前通过“跨节点融合算子”把多个通道节点拼成一个 batch 张量视图。
      - 推荐落地方式（与现有神经符号算子库对齐）：
        - 使用 `src/tools/multi_schemas.py` 的 `concatenate`（或专用 `stack_channels`）在 `axis=-1` 上合并通道，生成一个“融合节点”（例如 `x_all`），其 `results.ref/tst` 为 `{sample_id: (1,L,C)}`。
          - **强约束：parent 顺序必须等于 `dag_state.channels`**（例如 `"ch1,ch2,...,chC"`），否则拼接通道顺序会漂移，导致训练与解释不可复现。
        - 原始 `ch1..chC` 节点保留，用于解释性与溯源（可在报告里展示“每个通道对最终预测/算子重要性”的差异）。
      - 必须约定：通道顺序= `dag_state.channels` 的顺序；样本集合=所有通道 `sample_id` 的交集（缺失则丢弃并记录）。
   7) 多数据集数据工厂（参考 `vibench_fix/.../src/data_factory/README.md` 的接口范式，作为 PHMGA 的统一数据入口）
      - 目标：把“数据集选择 / 元数据解析 / task wrapper / DataLoader 构建”从 case 脚本里解耦出来，形成可扩展的多数据集入口，支撑论文 3 数据集与后续扩展。
      - 阶段建议：该模块建议在 P3（Phase 4）再引入；P0/P1/P2 优先把“单数据集 + 确定性训练 + 可解释反馈 + agent 闭环”跑稳，避免 reader/sampler/model 三处同时 debug。
      - 数据集命名约定（你已确认可任意命名）：
        - `dataset_name`/`data.name` 仅作为 **reader registry 的键**；命名可自定义，但必须在 data factory 的 reader 注册表中存在对应实现。
        - 论文/实验中不依赖“硬编码名称”，而是以 `case.yaml` 指向的 `data`/`task` 配置为准（保证可迁移与可复现）。
      - 推荐抽象（对齐该 README 的 mental model）：
        - **reader**：按 dataset_name/metadata 选择具体读取器（metadata.xlsx/CSV + h5 cache keyed by `Id`，样本 shape 通常 `(L,C)`）
        - **dataset_task**：任务封装（DG/CDDG/FS/GFS/pretrain/ID…），决定 batch 结构与采样策略
        - **factory**：`default`（eager）或 `id`（lazy/on-demand），决定是否预先构建数据集或仅按 ID 取数
        - **samplers**（可选）：few-shot/episodic 等自定义采样器（服务于域泛化/小样本实验）
        - 与 PHMGA 的映射（必须写死口径，避免各数据集“各写各的”）：
        - PHMGA 的 `initialize_state()` 不再直接依赖“某一个 metadata_path/h5_path”，而是接收 `config.data + config.task`，通过 data factory 输出：
          - `ref_ids/test_ids`（或 train/val/test ids）
          - `labels_ref/labels_tst`（严格边界）
          - `signals`（按需：eager 直接加载；lazy 仅返回可查询对象/句柄）
        - 对于 TSPN：无论 eager/lazy，都要能产出 `ch1..chC` 多节点与 `x_all` 融合节点（融合节点可在图内由 multi-op 生成）。
      - Task C（已定）：少样本 DG（Few-shot DG）
        - 建议 `task.dataset_task: "DG"`，并启用 episodic sampler（k-shot）。
        - 建议新增 `task.few_shot` 配置块（MVP）：
          - `n_way`（类别数/每 episode 类数）
          - `k_shot`（support 每类样本数）
          - `q_query`（query 每类样本数）
          - `n_episodes_{train,val,test}`（每阶段 episode 数）
        - 建议 `data.factory_name: "id"`：返回 ID-enriched batches（例如 `batch["x"]`, `batch["y"]`, `batch["file_id"]`），以便按需取数、降低 IO 并支持 episodic 采样器。
      - 文件边界（对齐 `doc/paper/goal.md`，减少耦合与返工）：
        - `case.yaml`：只放 `data/task` 与运行环境（路径/保存目录/流程开关）
        - `model_config.yaml`：只放 TSPN（结构/训练/解释），并作为外环智能体唯一允许修改的配置文件

2. 迁移并“仓库内化”你的可解释网络代码（保持原结构但做最小改造）
   1) 将下列文件按模块化方式迁入 PHMGA（建议路径：`src/model/explainable/`）：
      - `Feature_extract.py` → 特征算子集合（torch 版）
      - `Signal_processing.py` → 信号处理算子集合（torch 版）
      - `TSPN.py` → `Transparent_Signal_Processing_Network`
   2) 清理/隔离外部依赖与路径注入（如 `sys.path.append(current_dir)`），改为包内相对导入。
   3) 建立统一注册表（参考 Unified 中 `ALL_SP / ALL_FE` 的映射）：
      - `ALL_SP`: `'FFT'/'HT'/'WF'/'I'/...` → torch 算子类
      - `ALL_FE`: `'Mean'/'Std'/...` → torch 特征类
   4) 重复算子命名规则（对齐 `config_basic.yaml` 的“可重复列表”）：
      - YAML 允许同一 layer 中重复出现算子名（例如 `['I','WF','I']`）。
      - 构建时自动去重命名：`I, I_1, I_2 ...`（参考 Unified 的 `module_count` 逻辑）。
   5) 解释性“可观测点”固化为统一接口（供 Reporter/保存产物使用）：
      - `get_operator_importance()`：每层 `weight_connection` 的权重/softmax 后的通道分配统计。
      - `get_filter_params()`：`WaveFilters` 的 `f_c/f_b` 分布（mean/std/percentiles）与可复现的响应数据（数组即可）。
      - `get_feature_stats()`：特征层输出的 per-feature 分布/可分性摘要（可选，先留接口）。
   6) 迁移前关键代码 review（必须在 PHMGA 落地时修复/约束，否则训练与解释会不可信）：
      - **复数问题（高优先级）**：`FFTSignalProcessing` 当前返回 complex；但 `InstanceNorm1d/Linear` 默认不支持 complex，且后续 `torch.cat`/loss 也会受影响。
        - 处理策略：FFT 输出改为 `abs()`（幅值谱）或显式拆成 `real/imag` 两通道；并在 `ALL_SP` 中明确该算子的输出 dtype/spec。
      - **权重 in-place 变更（高优先级）**：`SignalProcessingLayer.forward()` 对 `self.weight_connection.weight.data` 做 softmax 并覆盖，这会破坏优化器状态与梯度语义。
        - 处理策略：改为“前向时计算 gating/softmax 权重”但不写回 parameter（例如 `w = softmax(self.weight_connection.weight, dim=0)` 然后用 `F.linear`）。
      - **`squeeze()` 维度风险（中优先级）**：`FeatureExtractorlayer` 使用 `.squeeze()`，当 batch=1 时可能误删 batch 维导致 shape 不稳定。
        - 处理策略：改为显式 reshape（例如 `res = torch.cat(..., dim=1)` 后仅 flatten feature 维，不对 batch 做 squeeze）。
      - **`CustomBatchNorm` 语义混淆（中优先级）**：其 `eps` 既当作“动量”又当作“数值稳定项”，容易导致训练不稳定与解释偏差。
        - 处理策略：优先替换为 `nn.BatchNorm1d`（或明确拆分 `momentum` 与 `eps` 两个参数并修正公式）。
      - **`WaveFilters` 参数维度一致性（中优先级）**：当前用 `args.scale` 初始化 `f_c/f_b` 的“滤波器个数”，但 forward 又按输入通道数切片；容易出现“参数数 < 输入通道数”的隐性截断。
        - 处理策略：把“滤波器数量/每层通道数”的决定权交给 config builder，保证初始化参数与实际通道完全一致（必要时每层独立参数）。
      - **模块顺序与重复命名（低优先级但影响可解释性）**：`ModuleDict` 的 key 顺序将影响“算子索引”的解释映射。
        - 处理策略：保证构建时顺序稳定（使用 `OrderedDict` 或 Python3.7+ 的插入顺序）并在报告里输出 key 列表。
   7) 结合 PHMGA 现有“神经符号算子库”（你要求新增的融合点，作为统一词表/能力来源）：
      - 目标：把 PHMGA 的算子注册表（`OP_REGISTRY`）作为**系统级的统一工具词表**，并与 TSPN 的 torch-side 模块建立“同名语义映射”，避免出现两套 operator vocabulary 互不相认。
      - 需要显式对齐/复用的算子库文件（作为主参考与扩展点）：
        - `src/tools/signal_processing_schemas.py`（`PHMOperator` / `OP_REGISTRY` / rank_class）
        - `src/tools/expand_schemas.py`（升维/时频表示等）
        - `src/tools/transform_schemas.py`（同维变换：滤波、hilbert、fft、psd…）
        - `src/tools/multi_schemas.py`（多变量/跨通道算子：subtract/coherence/concatenate…）
        - `src/tools/decision_schemas.py`（决策算子：后续可补齐真实可用的决策节点）
      - 建议的最小融合策略（MVP）：
        - 建立一张 `alias` 映射表：例如 `FFT ↔ fft`、`HT ↔ hilbert_envelope/ht`、`WF ↔ wavelet_filter/wave_filters`、`I ↔ identity`。
        - YAML 配置中允许同时出现两类 token：
          - `model.*`（TSPN torch-side SP/FE token，如 `FFT/HT/WF/I`）
          - `preprocess.ops`（PHMGA numpy-side op_name，如 `normalize/filter/hilbert_envelope/fft/psd/...`，来源于 `OP_REGISTRY`）
        - 智能体在生成配置时必须从这两类 whitelist 中选取，避免“凭空发明算子名”。

4. 用“智能体”自动化设置/优化模型配置参数（降低先验设计影响）
   1) 新增 `model_config_agent`（规划/提案）：
      - 输入：任务描述、数据摘要（通道数、长度、fs、类别数、样本规模）、当前/历史配置与评估反馈（reflection_history）
      - 输出：可验证的 YAML（或等价 dict），仅修改 `signal_processing_configs / feature_extractor_configs / args`
   2) 新增 `config_reflect_agent`（审视/约束检查 + 是否需要再搜索）：
      - 根据训练指标 + 结构约束失败原因，给出 `needs_revision` 与具体缺口（例如过拟合、算子冗余、通道/维度不匹配）。
   3) 将该“配置搜索环”接入外层图：`Plan(生成/改配置) -> Execute(训练评估) -> Reflect(是否继续)`。
   4) Agent 输出必须“结构化、可重放、可比较”（避免自然语言污染）：
      - `model_config_agent` 输出 JSON（再写入 YAML），字段仅限于 schema 允许的 key。
      - 每轮输出必须包含：`diff_summary`（人类可读）+ `config`（机器可读）。
   5) 搜索策略（先简单再复杂，控制组合爆炸）：
      - Phase-1：固定 layer_num/module_num，仅在候选算子集合中替换与排序（离散搜索）。
      - Phase-2：允许增减层/模块数，但必须满足约束；对每轮变更设置最大 edit distance。
      - Phase-3（可选）：把 `scale/out_channels/skip_connection` 也纳入搜索，但限制范围与步数。
   6) 优化目标的“口径”必须写死（否则智能体无法稳定收敛，也不利于复现）：
      - 主目标（必须）：`val_macro_f1` 或 `val_accuracy`（二选一，建议 macro-F1）。
      - 次目标（建议）：解释性/稀疏性正则（避免网络“看起来可解释但其实每个算子都均匀参与”）：
        - operator 重要性分布的熵（越低越稀疏，但要避免塌陷到单一算子导致性能崩）。
        - 模型复杂度惩罚（层数、总通道数、总参数量、训练耗时）。
      - 约束（必须）：任何违反 schema/shape/整除约束的配置都直接判定为 invalid（不进入训练）。
   7) 配置候选算子集合（必须 whitelist，避免 LLM 输出“不存在算子”）：
      - 初期推荐 whitelist：`I/WF/FFT/HT` + 少量稳定算子；等端到端稳定后再扩展到更多算子族。
      - 每轮变更必须输出“新增/移除/替换”的算子列表与原因（写入 `diff_summary`）。
   8) 外环“结构编辑（CRUD）”的工程化落地方式（按审稿/工程建议：**Immutable Config**）
      - 结论：不做“内存热更新（hot-swapping）”的 `nn.Module` 增删改查；Agent 永远只修改 `model_config.yaml` 文本，然后触发一个新的 train job（可选 warm start）。
      - Agent 的 CRUD 全部落在 config 层：
        - **Read**：导出结构快照（layer→token→op_uid、features、out_channels/scale、WF 参数统计）。
        - **Create/Update**：输出 `ConfigPatch`（见 `AGENT_IO.md`），修改 layer token 列表或超参。
        - **Delete（软删除）**：通过 `model.disabled_ops[op_uid]=1e-6` 禁用（不移除模块），并保存 `op_uid->module_key` 映射快照（见 `SPEC.md`）。
      - 红线：
        - 禁止 forward 内 `.data` 或 in-place 覆盖参数；门控必须显式参数化（`gate_logits`）。
        - 训练阶段不得读取 `labels_tst`，除非显式允许 `allow_test_labels_for_reporting=true`（见 `SPEC.md`）。

5. 在执行阶段增加深度模型训练/评估节点（替代或并行于 shallow_ml_agent）
   1) 新增 `deep_model_train_agent`：

      - 训练日志与指标（acc/f1/confusion matrix/校准等）写回 `PHMState`
   2) 新增可复现实验产物：
      - 保存最终 YAML 配置、权重 checkpoint、指标 JSON/Markdown
      - 与现有 `save_dir` 目录结构对齐
   3) 数据集构造建议（与 PHMGA 现状对齐，先跑通再优化）：
      - MVP 走“原始信号训练”：从根 `InputData` 直接取 `ref/tst` 信号与 `meta.labels`。
      - 说明：`dataset_preparer_agent` 当前做的是“特征文件→X/y”，但 TSPN 需要 `(B,L,C)`，两者不一致；因此不应强行复用。
      - **多节点→多通道融合（必须实现）**：对每个 `sample_id`，收集 `ch1..chC` 的 `(1,L,1)`，在 `axis=-1` 拼接为 `(1,L,C)`；再在 DataLoader batch 维堆叠为 `(B,L,C)`。
        - 推荐优先走“图内融合”：用 `multi_schemas.concatenate(axis=-1)` 生成 `x_all` 融合节点，再从 `x_all` 读取训练数据。
      - **标签编码（必须实现）**：`meta.labels` 的值可能是 int 或 str；训练前需构建稳定的 `label_to_index`（按排序/出现顺序），并把 mapping 保存进 artifacts 以便复现与报告解释。
      - **标签缺失处理（必须 fail-fast）**：若训练集（ref）中存在 `sample_id` 找不到 label（例如映射返回 `-1`），应直接报错并记录缺失列表；避免 silent drop 造成不可解释偏差。
   4) 训练稳定性与可重复性：
      - 固定 seed；保存 best checkpoint（按 val metric）。
      - 提供 CPU smoke-run（epoch=1, batch=4）用于快速验证与测试。
      - 训练/验证划分建议：从 `ref` 内按 `sample_id` 随机划分 train/val（固定 seed，默认 80/20）；`tst` 只用于最终评估，避免信息泄露。

6. 解释性输出对齐到 PHMGA 的报告系统（Reporter Agent）
   1) 抽取解释性证据：
      - 每层 `weight_connection` 的权重分布（算子重要性/通道分配）
      - 若有 `WaveFilters`，导出 `f_c/f_b` 的统计与可视化
      - 特征层输出的 feature-wise 贡献（可用权重/梯度或消融）
   2) Reporter 生成的 Markdown 报告中：
      - 结论 + 指标
      - “网络结构（来自 YAML）→ 证据链”的逐层解释
      - 附上 DAG（若将模型配置也纳入 DAGTracker）或单独的 workflow 图
   3) 解释性最小可交付（MVP）：
      - Operator importance：每层 top-k 算子（按权重聚合）+ 可视化用数据（CSV/npz）。
      - Filter params：`f_c/f_b` 的分布统计（mean/std/percentiles）+ 典型滤波器响应（数组）。
      - Operator importance 的计算口径（建议在代码与报告中固定，避免“解释漂移”）：
        - `SignalProcessingLayer` 将 `out_channels` 分割成 `module_num` 段，每段对应一个算子模块。
        - 可定义每个算子的重要性为：该算子对应段在 `weight_connection`（以及可选 `skip_connection`）上的权重范数聚合（例如 L1/L2），再做 softmax/归一化得到可比较分数。
        - 报告必须同时输出：算子 key 列表、每层 `module_num`、`out_channels`、以及归一化方式（L1/L2/softmax）。

7. 集成到 PHMGA 的 case 与运行入口
   1) 扩展 `config/case*.yaml`：新增 `model_config_path` 或内联 `model:` 段落用于选择 `TSPN` 工作流。
   2) 新增/修改 `src/phm_outer_graph.py`：
      - 增加一个 executor graph 变体：`prepare -> train_tspn -> report`
      - 或提供开关：`train_backend: shallow_ml | tspn`
   3) 建议的运行方式（面向复现实验）：
      - `case.yaml` 只负责数据与流程开关；`model_config.yaml` 独立维护网络/训练/解释配置。
      - 输出目录：`save/<case_name>/tspn/<timestamp>/`，保存 config、ckpt、metrics、explain artifacts。
      - 多数据集统一入口：`case.yaml` 中加入 `data:` 与 `task:` 块（参考 data_factory README），通过工厂构建 dataloaders/ids，避免每个 case 自己 hardcode `metadata_path/h5_path/ref_ids/test_ids`。
   4) 建议增加 “TSPN-only 快速路径”（降低 LLM 成本，便于迭代模型结构）：
      - 当 `train_backend=tspn` 且用户不需要 numpy-DAG 产物时，可跳过**LLM 驱动的 builder loop**，直接走确定性路径：
        - 从 `initialize_state()` 得到的 `ch1..chC` 多节点信号出发；
        - 训练前执行一次“跨通道融合”（二选一，效果等价）：
          - 图内融合：调用 `multi_schemas.concatenate(axis=-1)` 生成 `x_all` 节点；
          - 训练内融合：在 `deep_model_train_agent` 内对齐 `sample_id` 后直接 `np.concatenate(..., axis=-1)` 生成 `(B,L,C)`。
        - 强制保存 `channels` 顺序与 `sample_id` 列表，确保可复现。
      - 当 `train_backend=both` 时：先跑 builder（为 shallow_ml 产生特征/数据集），再跑 TSPN（原始信号端到端），最后在 report 中做对比表。

8. 验证与测试（最小可用到可扩展）

   2) 冒烟训练：小数据子集 1~2 epoch，确保端到端可运行与产物落盘。
   3) 依赖补齐：
      - 将 `einops` 等与平台无关依赖加入 `requirements.txt`。
      - `torch` 建议作为可选/平台依赖：在 README 中给出 CPU/CUDA 安装指引；必要时提供 `requirements-torch.txt`（避免在不同机器上 pip 拉错 CUDA 轮子）。
   4) 回归边界用例（必须覆盖）：

## 进一步 review：系统级一致性与可复现实验要求（建议纳入验收）

1) **与 PHMGA 外层图一致性**
   - PHMGA 当前 builder loop 是“LLM 生成 numpy 算子 DAG → 执行 → reflect”；TSPN 是“端到端可训练模型”。
   - 推荐落地路径：将 TSPN 作为 executor graph 的一个分支（`train_backend=tspn|both`），不要强行塞进现有 DAG builder loop（避免两套搜索互相干扰）。
   - **现状差距提醒**：当前 `src/cases/case1.py` 仅运行 builder workflow（executor workflow 被注释），因此“训练后端分支”需要在 case 入口显式启用/补齐，否则配置正确也不会执行到训练。

2) **数据拆分与评价协议（避免“看起来能跑但不可比较”）**
   - `ref_ids/test_ids` 已天然提供 train/test；但 TSPN 训练仍建议从 ref 内部分出 val（固定 seed，比例如 80/20）。
   - 输出指标至少包含：test accuracy、macro-F1、confusion matrix（Markdown/CSV），并保存预测结果（sample_id → pred/true/proba）。

3) **配置与产物的可追溯性（解释性实验的最低要求）**
   - 每次 run 必须保存：
     - `model_config.yaml` 原样拷贝（含 hash 或版本号）
     - 随机种子、git commit（或至少当前工作区 dirty 标记）、依赖版本摘要（pip freeze 可选）
     - checkpoint（best/last）与 metrics.json
   - 解释性产物必须带“层号/算子key/时间戳/数据集信息”，否则后续无法对齐报告与复现。

4) **智能体改配置的安全边界（避免不可控写文件/路径注入）**
   - LLM 只能改 `model_config` 的 whitelist 字段，不能改 `save_dir`、不能改任意路径、不能引入新 import。
   - 每轮改动先过 schema 校验 + 约束校验；失败则回退并写清错误原因到 `reflection_history`。

5) **关键接口函数建议（降低集成耦合度，便于单测）**
   - `build_multichannel_dataset(state, split: 'ref'|'tst') -> (X: np.ndarray, y: np.ndarray, sample_ids: list[str])`
     - 输入来自 `state.dag_state.nodes[ch].results[split]`
     - 输出 `X` 形状 `(N,L,C)`（或 `(N,1,L,C)` 由训练代码决定），并返回 `sample_ids` 方便写预测结果对齐。
   - `validate_model_config_against_data(model_cfg, X, y)`：
     - 校验 `in_dim==L`、`in_channels==C`、`num_classes==len(unique(y))`；失败必须 fail-fast。

6) **数据加载与标签的潜在坑（建议提前修复/写明约束）**
   - `load_signal_data()` 当前对 HDF5 数据做 `np.squeeze()` 后再与 `(sample_length, num_channels)` 比较：
     - 若 `num_channels == 1`，squeeze 很可能把二维 `(L,1)` 压成一维 `(L,)`，导致 shape mismatch 而被跳过。
     - 这会直接影响“单通道数据集”的可用性与 TSPN 的 `in_channels` 推断。
   - 建议策略（择一）：
     - A：修复加载逻辑（仅 squeeze 多余 batch 维，不 squeeze channel 维）。
     - B：在文档/校验中声明：当前仅支持 `num_channels>=2`，并在 case 初始化阶段 fail-fast 给出明确错误。

7) **“可解释”的验收标准建议（避免只输出一堆数字但无法解释）**
   - 必须能回答三类问题，并在报告中有对应小节：
     - 哪些算子/层最重要？（层级、算子 key、分数、归一化口径）
     - `WaveFilters` 学到了什么？（`f_c/f_b` 分布 + 典型响应/频带位置）
     - 特征层输出是否与类别相关？（至少给出类间差异的统计/可视化数据，哪怕是简化版）
   - 必须提供“稳定性检查”（建议至少一种）：
     - 重新训练不同 seed，top-k 算子是否一致（Jaccard/Overlap）。
     - 小幅噪声扰动/随机丢样本时，算子重要性排序是否大幅漂移。

## 进一步 review：解释性语义与实现细节的“隐藏不一致”（建议提前约束/修复）

1) **“算子重要性”是否真的等价于“算子被使用”**
   - 当前 `SignalProcessingLayer` 的结构是：`norm -> Linear(in_channels→out_channels) -> split(out_channels by module_num) -> per-op module -> cat`。
   - 这意味着：
     - Linear 会先把输入通道做混合，再把混合后的通道切片分配给各个算子；
     - 因此“某个算子对应的通道段权重很大”更接近于“该通道段被强调”，并不严格等价“该算子对原始物理通道的重要性”。
   - 建议（先不改结构，先把口径写死）：
     - 报告中明确“重要性=对输出通道段的贡献权重”，而不是“原始通道的物理贡献”；
     - 后续若要更强解释性，再引入更直接的 gating（例如每个算子一个标量 gate/attention）。

2) **FFT/Hilbert/WaveFilters 的“物理频率解释”需要 fs 映射**
   - `WaveFilters` 里 `omega` 目前是 0~0.5 的归一化频率（Nyquist=0.5），并不直接是 Hz。
   - 建议：
     - 在解释性产物里同时输出归一化频率与 Hz（`f_hz = omega * fs`）；
     - 若 `fs` 不可用，报告必须注明“频率为归一化单位”。

3) **torch 侧算子与 PHMGA numpy 算子存在“同名不同义”风险**
   - 例如 `mean/std/var/entropy`：PHMGA 里是 numpy 聚合算子（AggregateOp），Unified 里是 torch feature 提取模块。
   - 建议：
     - 在 `src/model/explainable/` 内部统一用前缀/命名空间（例如 `TorchMeanFeature` 或在注册表里加域名 `fe:Mean`、`sp:FFT`）；
     - 报告生成时打印完整路径/类别（SP vs FE）避免歧义。

4) **依赖管理：`torch` 不建议直接 pin 进 `requirements.txt`**
   - 原因：torch 轮子与 CUDA/平台强绑定，pip 直接依赖容易在不同机器上失败或拉错版本。
   - 建议：
     - README/文档里提示用户按平台安装 torch（CPU/CUDA），PHMGA 只做 import 级别的可选依赖检查；
     - 或新建 `requirements-torch.txt` / `extra_requires`（若未来做 packaging）。

5) **标签与数据泄露边界（建议文档写清 + 代码保护）**
   - 当前初始化把 `ref_labels` 与 `test_labels` 合并到 `meta.labels`（用于评估很方便）。
   - 但在"真实部署"或某些 benchmark 设置里，test label 应视为未知；训练/配置搜索不应读取 test label。
   - 建议：
     - state/meta 同时存 `labels_ref` 与 `labels_tst`，并在训练代码中强制只用 `labels_ref`；
     - 评估阶段才允许读取 `labels_tst`（若存在），否则只输出预测不算指标。

建议在 PHMGA 增加一个“最小可用”的 data factory 层（命名可沿用 `data_factory`），核心目标是让 3 个数据集共用同一套接口：

- `build_data(config.data, config.task) -> dict`
  - 返回：`ref_ids/test_ids/(val_ids)`、`labels_ref/labels_tst`、以及可选的 `dataloaders`（default eager）或 `id_accessor`（id-based lazy）
- reader 的扩展规则（与 README 对齐）：
  - 新增 dataset：实现 `reader/<dataset_name>.py`，并注册到 factory
  - 新增任务：实现 `dataset_task/<task_name>.py`，决定 batch 结构与采样器
- 与 PHMGA 初始化的对齐：
  - `initialize_state()` 从 `build_data()` 的输出构建 `ch1..chC` 节点（多节点）；
  - 若配置要求（TSPN 或多通道操作），再用 multi-op 生成 `x_all` 节点。

```python
# src/model/explainable/config_schema.py（示意，推荐与 Pydantic v2 对齐）

from typing import Dict, List, Literal, Any
from pydantic import BaseModel, Field, field_validator, model_validator


class PreprocessConfig(BaseModel):
    """numpy-side 预处理 DAG（来自 OP_REGISTRY 的 op_name）"""
    ops: List[Dict[str, Any]] = Field(default_factory=list, description="[{op_name, params, parents}]")


class ModelArgs(BaseModel):
    """网络结构参数"""
    device: Literal["cuda", "cpu"] = "cuda"
    num_classes: int
    in_dim: int
    in_channels: int
    out_channels: int
    scale: int = 4
    skip_connection: bool = True

    # WaveFilters 参数
    f_c_mu: float = 0.0
    f_c_sigma: float = 0.1
    f_b_mu: float = 0.0
    f_b_sigma: float = 0.1


class TrainConfig(BaseModel):
    learning_rate: float = 0.001
    batch_size: int = 64
    num_epochs: int = 20
    weight_decay: float = 0.0001
    seed: int = 42


class ExplainConfig(BaseModel):
    export_operator_weights: bool = True
    export_filter_params: bool = True
    export_feature_stats: bool = False


class TSPNModelConfig(BaseModel):
    name: Literal["tspn"] = "tspn"
    signal_processing_configs: Dict[str, List[str]]  # layer_name -> ops (允许重复)
    feature_extractor_configs: List[str]
    disabled_ops: Dict[str, float] = Field(
        default_factory=dict,
        description=(
            "soft-delete: op_uid -> gate (e.g., 1e-6). "
            "op_uid 必须稳定可复现：op_uid = L{layer_idx}:{token}:{occurrence_idx}，"
            "并在 artifacts 中保存 op_uid -> module_key 的映射快照。"
        ),
    )


class TSPNConfig(BaseModel):
    """TSPN 完整配置（与 doc/plan 的 YAML 口径保持一致）"""
    model: TSPNModelConfig
    args: ModelArgs
    train: TrainConfig
    explain: ExplainConfig = Field(default_factory=ExplainConfig)
    preprocess: PreprocessConfig = Field(default_factory=PreprocessConfig)

    @field_validator("model")
    @classmethod
    def check_ops_whitelist(cls, v: TSPNModelConfig):
        allowed = {"I", "WF", "FFT", "HT"}  # MVP whitelist，后续可扩展
        for _, layer_ops in v.signal_processing_configs.items():
            for op in layer_ops:
                if op not in allowed:
                    raise ValueError(f"Unknown TSPN op: {op}. Allowed: {sorted(allowed)}")
        return v

    @model_validator(mode="after")
    def validate_divisibility(self):
        out_channels = self.args.out_channels * self.args.scale
        for layer_name, layer_ops in self.model.signal_processing_configs.items():
            if not layer_ops:
                continue
            module_num = len(layer_ops)
            if out_channels % module_num != 0:
                raise ValueError(
                    f"{layer_name}: out_channels*scale={out_channels} must be divisible by module_num={module_num}"
                )
        return self
```

### 三、数据转换函数

```python
# src/model/explainable/data_utils.py（示意：优先从融合节点 x_all 读；否则从 ch1..chC 融合）

import numpy as np
from typing import Tuple, List
from ..states.phm_states import PHMState

def build_multichannel_dataset(
    state: PHMState,
    split: Literal['ref', 'tst'] = 'ref'
) -> Tuple[np.ndarray, np.ndarray, List[str]]:
    """
    从 PHMGA 多节点数据构建 TSPN 所需的 (N, L, C) 数据集

    Args:
        state: PHMState 实例
        split: 'ref' 或 'tst'

    Returns:
        X: (N, L, C) 信号数组
        y: (N,) int64 标签数组
        sample_ids: 样本ID列表（与X行对齐）
    """
    channels = state.dag_state.channels
    all_nodes = state.dag_state.nodes

    # 1) 如果已有融合节点 x_all，优先从其 results 读取（图内融合路径）
    fused = all_nodes.get("x_all")
    if fused is not None and isinstance(getattr(fused, "results", None), dict):
        fused_results = fused.results.get(split, {})
        if fused_results:
            sample_ids = sorted(fused_results.keys())
            first = fused_results[sample_ids[0]]  # (1, L, C)
            L, C = int(first.shape[1]), int(first.shape[2])
            X = np.zeros((len(sample_ids), L, C), dtype=np.float32)
            y = np.zeros(len(sample_ids), dtype=np.int64)

            # labels：严格区分 ref/tst，训练阶段只用 labels_ref
            labels_map = state.labels_ref if split == "ref" else (state.labels_tst or {})
            for i, sid in enumerate(sample_ids):
                X[i] = fused_results[sid][0]  # (L, C)
                y[i] = labels_map.get(sid, -1)
            return X, y, sample_ids

    # 2) 否则从 ch1..chC 多节点融合（训练内融合路径）
    channel_data = {}  # {channel: {sample_id: (1, L, 1)}}
    sample_id_sets = []  # 每个通道的 sample_id 集合

    for ch in channels:
        node = all_nodes.get(ch)
        if node is None:
            continue

        # 获取信号数据
        results = node.results.get(split, {})
        if not results:
            continue

        # 记录
        channel_data[ch] = results
        sample_id_sets.append(set(results.keys()))

    # 取交集（只保留所有通道都有的样本）
    if not sample_id_sets:
        raise ValueError(f"No data found for split='{split}'")

    common_sample_ids = sorted(set.intersection(*sample_id_sets))

    # 构建 X, y（labels：严格区分 ref/tst）
    labels_map = state.labels_ref if split == "ref" else (state.labels_tst or {})
    n_samples = len(common_sample_ids)
    if n_samples == 0:
        raise ValueError("No common samples across all channels")

    # 从第一个有效通道推断形状
    first_ch = next(iter(channel_data.keys()))
    first_sample_id = common_sample_ids[0]
    first_signal = channel_data[first_ch][first_sample_id]
    L = first_signal.shape[1]  # 时间长度
    C = len(channels)  # 通道数

    X = np.zeros((n_samples, L, C), dtype=np.float32)
    y = np.zeros(n_samples, dtype=np.int64)

    for i, sample_id in enumerate(common_sample_ids):
        for j, ch in enumerate(channels):
            signal = channel_data[ch][sample_id]
            X[i, :, j] = signal[0, :, 0]  # (1, L, 1) -> (L,)

        # 标签（从任意通道取，应该一致）
        y[i] = labels_map.get(sample_id, -1)

    return X, y, common_sample_ids


def validate_model_config_against_data(
    model_config: TSPNConfig,
    X: np.ndarray,
    y: np.ndarray
) -> None:
    """
    校验模型配置与数据是否匹配

    Raises:
        ValueError: 配置与数据不匹配
    """
    N, L, C = X.shape
    # y 中不应出现 -1（unknown）参与统计；unknown 的存在应在更早阶段 fail-fast
    y_valid = y[y >= 0]
    num_classes = len(np.unique(y_valid))

    args = model_config.args

    errors = []
    if args.in_dim != L:
        errors.append(f"in_dim={args.in_dim} != data L={L}")
    if args.in_channels != C:
        errors.append(f"in_channels={args.in_channels} != data C={C}")
    if args.num_classes != num_classes:
        errors.append(
            f"num_classes={args.num_classes} != unique labels={num_classes}"
        )

    if errors:
        raise ValueError("Config validation failed:\n  - " + "\n  - ".join(errors))
```

### 四、配置 Builder

```python
# src/model/explainable/config_builder.py

import yaml
from collections import OrderedDict
from typing import Dict, List
from .registry import ALL_SP, ALL_FE
from .signal_processing import SignalProcessingModuleDict
from .feature_extract import FeatureExtractionModuleDict

class TSPNConfigBuilder:
    """从 YAML 构建 TSPN 网络组件"""

    @staticmethod
    def build_signal_processing_modules(
        config: Dict,
        args
    ) -> List[SignalProcessingModuleDict]:
        """
        构建信号处理模块列表（处理重复算子命名）

        Args:
            config: signal_processing_configs 字典
            args: 模型参数

        Returns:
            每层的 SignalProcessingModuleDict 列表
        """
        modules_list = []

        for layer_name, layer_ops in config.items():
            if not layer_ops:  # 跳过空层
                continue

            signal_module = OrderedDict()
            module_count = {}  # 跟踪每个算子名出现的次数

            for op_name in layer_ops:
                # 获取算子类
                op_class = ALL_SP.get(op_name)
                if op_class is None:
                    raise ValueError(f"Unknown operator: {op_name}")

                # 处理重复命名
                if op_name in module_count:
                    module_count[op_name] += 1
                    unique_name = f"{op_name}_{module_count[op_name]}"
                else:
                    module_count[op_name] = 0
                    unique_name = op_name

                # 实例化算子
                signal_module[unique_name] = op_class(args)

            modules_list.append(SignalProcessingModuleDict(signal_module))

        return modules_list

    @staticmethod
    def build_feature_extractor_modules(
        config: List[str]
    ) -> FeatureExtractionModuleDict:
        """构建特征提取模块"""
        feature_module = OrderedDict()

        for feature_name in config:
            feature_class = ALL_FE.get(feature_name)
            if feature_class is None:
                raise ValueError(f"Unknown feature: {feature_name}")
            feature_module[feature_name] = feature_class()

        return FeatureExtractionModuleDict(feature_module)

    @staticmethod
    def load_config(yaml_path: str) -> Dict:
        """加载 YAML 配置文件"""
        with open(yaml_path, 'r') as f:
            return yaml.safe_load(f)
```
